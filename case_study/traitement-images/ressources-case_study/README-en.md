# Parking case study resources

The 177 photographs and occupancy labels come from camera 6 of **CNRPark+EXT**, published by Amato, Carrara, Falchi, Gennaro, and Vairo: <https://cnrpark.it/>. The official site lists the dataset under the **Open Data Commons Open Database License (ODbL) 1.0**. These photographs are copies of files already archived in the course, renamed `R00`, `C001` to `C080`, `V001` to `V056`, and `E001` to `E040`. They were neither redrawn nor generated by AI.

Filenames are the same in both language editions. The `ressources-case_study/` folder contains the following resources:

| File or folder | Description |
|:---|:---|
| `images/` | RGB photographs used by the scripts, including the reference image `R00.jpg`. |
| `images.csv` | Image IDs, filenames, dates, times, weather conditions, and set membership. |
| `parking_spaces.csv` | IDs of the eight parking spaces and coordinates of their rectangles (`x0`, `y0`, `x1`, `y1`). |
| `labels_tuning.csv` | Free/occupied labels for the tuning set. |
| `labels_validation.csv` | Free/occupied labels for the validation set. |
| `reference_spaces.png` | Grayscale preview of `R00`, showing parking-space rectangles and IDs. |
| `requirements.txt` | List of Python dependencies. |

Occupancy labels were taken from the official `CNRPark+EXT.csv` metadata by matching camera, date, time, and parking-space ID to each photograph. `0` means empty and `1` means occupied. The rectangles come from `camera6.csv` in the local archives. Its coordinates refer to original $2592 \times 1944$ images; they were scaled and rounded for the distributed $1000 \times 750$ images. A rectangle identifies a **parking space**, not the outline of a vehicle.

Eight times between approximately 8 a.m. and 4 p.m. were selected from each of 22 analyzed days, without using occupancy labels to choose the frames. Evaluation labels are held by the instructor. `R00` shows all eight spaces empty and is used only as a reference.

Some CSV column names follow the original French course convention. The common `tools.py` adapts them to the English keys used by the scripts. In `images.csv`, `fichier` means filename, `jour` means day, `heure` means time, `meteo` means weather, and `partition` means split. In the label files, `place_id` means parking-space ID and `occupation` means occupancy. In `images.csv`, the value `calibrage` in the `partition` column identifies the tuning set. The scripts write this as `calibration` in the result column `split`. You do not need to rename these fields or files.

Days do not overlap across the tuning, validation, and evaluation sets.
